# Ранкова мотивація ☀️

PWA-застосунок: щодня о **8:00** (за Варшавою) на телефон приходить push-сповіщення з **2–3 мотиваційними цитатами** з твого пулу, а в застосунку однією кнопкою вмикається твій музичний трек. Цитати обираються випадково **без повторів** до вичерпання пулу (shuffle bag), після чого цикл починається заново.

## Як це влаштовано

```
┌─ Телефон (Samsung / iPhone) ──────────────┐
│  PWA на GitHub Pages                      │
│  «Сьогодні» · «Цитати» · «Історія» ·      │
│  «Налаштування» + service worker (push)   │
└──────────────▲───────────────▲────────────┘
               │ push          │ дані, трек
┌──────────────┴─────┐  ┌──────┴─────────────┐
│  GCP ВМ            │  │  Supabase          │
│  systemd-таймер    │─▶│  quotes, history,  │
│  send_morning.py   │  │  підписки, Storage │
└────────────────────┘  └────────────────────┘
```

Структура репозиторію:

- `CLAUDE.md` — контекст для ШІ-агентів (архітектура, інваріанти, типові задачі)
- `app/` — React/Vite PWA (фронтенд)
- `supabase/schema.sql` — схема бази даних
- `sender/` — скрипт розсилки + systemd-юніти для ВМ
- `.github/workflows/deploy.yml` — автодеплой на GitHub Pages

---

## Крок 1. Supabase

1. Створи новий проєкт на [supabase.com](https://supabase.com) (безкоштовного тарифу достатньо).
2. Відкрий **SQL Editor → New query**, встав увесь вміст `supabase/schema.sql` і натисни **Run**.
3. Збережи собі два значення з **Settings → API**:
   - **Project URL** — знадобиться і фронтенду, і скрипту;
   - **anon public** ключ — для фронтенду;
   - **service_role** ключ — тільки для скрипта на ВМ (секретний, нікуди не комітити!). 

## Крок 2. VAPID-ключі

Це пара ключів для web-push. Згенеруй один раз на своєму компі:

```bash
npx web-push generate-vapid-keys
```

Отримаєш **Public Key** (піде у фронтенд) і **Private Key** (піде в `.env` на ВМ).

## Крок 3. Налаштування фронтенду

1. Відкрий `app/src/config.js` і встав свої `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `VAPID_PUBLIC_KEY`.
2. Відкрий `app/vite.config.js` і в полі `base` вкажи назву **свого** репозиторію, наприклад `'/morning-motivation/'`.

## Крок 4. Деплой на GitHub Pages

1. Створи репозиторій на GitHub (можна приватний — Pages на приватних репо доступний з планом Pro; на безкоштовному зроби публічний).
2. Запуш увесь цей проєкт у гілку `main`.
3. У репозиторії: **Settings → Pages → Source: GitHub Actions**.
4. Workflow збере застосунок сам. Адреса буде `https://<нік>.github.io/<репозиторій>/`.

> Локальна перевірка перед пушем: `cd app && npm install && npm run dev`

## Крок 5. Розсилка на ВМ

На своїй GCP ВМ:

```bash
sudo mkdir -p /opt/morning-push && sudo chown $USER /opt/morning-push
cd /opt/morning-push
# скопіюй сюди вміст папки sender/ (scp, git або rsync)

python3 -m venv venv
venv/bin/pip install -r requirements.txt

cp .env.example .env
nano .env   # встав SUPABASE_URL, service_role ключ, приватний VAPID, свій mailto:
```

Перевір, що все живе (телефон уже має бути підписаний — див. крок 6):

```bash
set -a; source .env; set +a
venv/bin/python send_morning.py --dry-run   # покаже добірку, нічого не надішле
venv/bin/python send_morning.py --test      # реальний тестовий push на телефон
```

Увімкни щоденний запуск о 8:00:

```bash
sudo cp morning-push.service morning-push.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now morning-push.timer

systemctl list-timers morning-push.timer   # коли наступний запуск
journalctl -u morning-push.service -n 30   # логи останніх розсилок
```

`Persistent=true` у таймері означає: якщо ВМ була вимкнена о 8:00, розсилка піде одразу після ввімкнення.

## Крок 6. Телефон

**Samsung (Android), браузер Chrome:**

1. Відкрий адресу застосунку → під час першого запуску придумай **PIN**.
2. На вкладці «Сьогодні» натисни **«Увімкнути ранкові сповіщення»** і дозволь їх.
3. Меню Chrome (⋮) → **«Додати на головний екран»** → «Встановити».
4. У «Налаштуваннях» застосунку натисни **«Тестове сповіщення»** — має зʼявитись одразу.

**iPhone (iOS 16.4+):**

1. Відкрий адресу в Safari → **Поділитись → На екран «Домівка»**.
2. Відкрий застосунок **з іконки** → введи PIN → увімкни сповіщення.

## Крок 7. Наповнення

- **Цитати**: вкладка «Цитати». Для масового імпорту натисни **«Додати списком»** і встав багато цитат одним текстом — кожна з нового абзацу.
- **Музика**: «Налаштування → Завантажити трек» (MP3, рекомендовано до 45 МБ). Заміна треку — та сама кнопка. Трек кешується і грає навіть офлайн.

## Повсякденне

| Дія | Де |
| --- | --- |
| Додати / видалити цитату | Вкладка «Цитати» (телефон або той самий URL на компі) |
| Замінити трек | «Налаштування → Замінити трек» |
| Змінити PIN | «Налаштування → PIN» |
| Подивитись минулі ранки | Вкладка «Історія» |
| Змінити час розсилки | На ВМ: відредагуй `OnCalendar` у `/etc/systemd/system/morning-push.timer`, потім `sudo systemctl daemon-reload && sudo systemctl restart morning-push.timer` |
| Логи розсилки | `journalctl -u morning-push.service` |

## Відомі обмеження

- **Музика не вмикається сама** зі сповіщенням — автовідтворення блокують і Android, і iOS. Один тап по сонцю на екрані «Сьогодні».
- **PIN — це замок, а не шифрування**: він захищає від випадкових очей, але anon-ключ Supabase присутній у коді сторінки. Для мотиваційних цитат цього достатньо; за потреби згодом можна перейти на Supabase Auth.
- **Samsung і батарея**: якщо помітиш, що пуші запізнюються, — виключи Chrome з оптимізації батареї (Налаштування → Догляд за пристроєм → Батарея).
- Сповіщення приходить зі **стандартним системним звуком** — власний звук у web-push поставити не можна.

## Якщо щось не працює

- *Push не приходить*: перевір `journalctl -u morning-push.service`; переконайся, що в «Налаштуваннях» застосунку стан «Увімкнено на цьому пристрої»; спробуй `--test` з ВМ.
- *«Немає звʼязку з базою» на старті*: перевір значення в `app/src/config.js` і що `schema.sql` виконано.
- *Трек не грає*: перевір, що файл завантажився («Налаштування» покажуть дату), і що бакет `music` створено кроком 1.
